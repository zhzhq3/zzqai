# 构建与安装

## 1. 环境

| 项 | 要求 |
|---|---|
| 系统 | Windows（Q3 本体在 Windows 上跑；Linux/macOS 编译需 wine 跑 `bin/*.exe`） |
| Shell | Git Bash（或任意能跑 bash 的环境） |
| 引擎 | 任何支持 QVM 的 Q3 引擎。本项目在 **quake3e**（Vulkan 分支）上验证 |
| 编译工具 | 仓库自带 `bin/lcc.exe`、`bin/q3cpp.exe`、`bin/q3rcc.exe`、`bin/q3asm.exe` |
| 打包工具 | Python 3（`tools/pack_release.sh` 用） |

**不需要** MSVC、不需要 Quake 3 SDK、不需要 FTEQCC。

---

## 2. 编译 qagame.qvm

```bash
bash build/build_qagame.sh
```

流程（与 id 官方 `game.bat` 完全一致，只是脚本化）：

```
每个 .c  ── q3lcc -DQ3_VM -S -Wf-target=bytecode -Wf-g ──▶ .asm
所有 .asm ── q3asm -f qagame.list ──▶ vm/qagame.qvm
```

要点：

- `-DQ3_VM` 必须加，否则会走原生 DLL 分支。
- `g_syscalls.asm` 必须在文件清单**最后**，它提供 `trap_*` 的 syscall 编号。
- 源文件清单见 `build/build_qagame.sh` 里的 `FILES`，与 brainworks 原版一致，
  **只多了一个 `ai_duel`**。

产物：`code/game/vm/qagame.qvm`（约 580 KB）。

预期输出末尾：

```
0 total errors
code segment:  552192
...
Writing to .../vm/qagame.qvm
```

> 编译时出现 `../g_spawn.c:174: warning: empty declaration` 是**原版自带**的，与本项目无关。

## 3. 打包成 pk3

```bash
python --version || echo "需要 Python 3"

bash tools/pack_release.sh \
     release/brainworks.pk3 \
     release/brainworks-new.pk3 \
     Z:/path/to/zzqbot-assets
```

脚本做三件事：

1. 用 `release/qagame.qvm` 覆盖 pk3 内的 `vm/qagame.qvm`
2. 把 `botfiles/` 下的 zzqBOT 角色定义打进去
3. 若给了资源目录，把 `models/players/War`、`sound/player/War` 等一并打进去

### 为什么必须重打包 pk3？

Q3 的 `FS_AddGameDirectory` 让 **gamedir 的 pk3 优先于 gamedir 下的松散文件**。
把 `qagame.qvm` 丢在 `brainworks/vm/` 目录里是**不会**被加载的 —— 引擎会继续用
pk3 里的那一份。这是最容易浪费一整天的坑。

### 手动打包（不用脚本）

`.pk3` 就是 `.zip`。用任意 zip 工具把 `vm/qagame.qvm` 替换进去即可，
**注意保持 zip 内的路径为 `vm/qagame.qvm`**（不能多一层目录）。

## 4. 安装到游戏

```
<Quake3>/brainworks/
├── brainworks.pk3        ← 替换成新打包的
├── q3config.cfg
└── ...
```

**先备份原 pk3。**

启动后控制台：

```
exec zzqbot.cfg
```

或命令行直接开：

```
quake3e.x64.exe +set fs_game brainworks +devmap q3dm4 +exec zzqbot.cfg
```

## 6. 踩坑记录

### 6.1 新增 QVM cvar 不生效

**症状**：`cvarlist` 显示自己设的值（比如 `bot_duel_debug is:"1"`），
但代码里读到的永远是默认值，毫无反应。

**原因**：brainworks 的 cvar 不是每帧自动同步的。注册（`trap_Cvar_Register`）
只发生一次，之后必须显式 `trap_Cvar_Update()` 才会把控制台的值拉进 VM 变量。

**修法**：在 `ai_vars.c` 的 `LevelUpdateVariables()` 里补一行：

```c
trap_Cvar_Update(&bot_duel);
trap_Cvar_Update(&bot_duel_move);
trap_Cvar_Update(&bot_duel_debug);
trap_Cvar_Update(&bot_duel_report);
```

本项目 M1/M2 也踩过同一个坑。

### 6.2 `sv_cheats` 被 ROM 锁

某些发行版（含 Quake 3 的一些重制版）把 `sv_cheats` 锁在 ROM 里，
`give all`、`set sv_cheats 1` 都会失败。用 **`devmap`** 开图（它内部强制开 cheats）。

### 6.3 机器人进场很晚

`wait N` 里的 N 是**客户端帧**（quake3e 默认约 57 fps，所以 `wait 1500` ≈ 26 秒）。
机器人要在服务器跑一段时间后才 `entered the game`，脚本里 `wait` 给少了会看到
"什么都没发生"。本仓库的验证配置从 1500 帧起步。

### 6.4 CTF 默认开着

如果服务器默认 `ctf 1`，`addbot` 的参数会变成 `<队名> <名字> <皮肤>`，
机器人会全部被叫成 "male"。先 `set ctf 0`。

### 6.5 不要用"有没有某个字符串 / 有没有 call 指令"判断改动是否生效

编译器会内联（`SetRespawn()` 之类）并把字符串折叠成立即数，
所以二进制里搜不到不代表没编进去。要看它引用的 `.rdata` 常量，
或者干脆用运行时的诊断输出 ——**本项目所有功能都配了可打印的诊断**，就是为此。

### 6.6 后台启动的进程会被 shell 回收

用 `nohup ... &` 起游戏然后 `sleep`，shell 超时会把子进程一起带走。
**前台跑**（直接 `timeout 300 ./quake3e... +exec ...`）最稳。
