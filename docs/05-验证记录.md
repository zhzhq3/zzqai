逐条核对都合理：

- `优势比 40.00, 敌方 3` → 压上（对面 3 点血，收人头）

### 2.3 汇总报告

```
$ bot_duel_report 1
===== zzqAI M3/M4 决斗态势报告 =====
机器人    态势   优势比 压上   脱离   绕圈换向
AI-One       压上          5.40 19       15       7
AI-Two       压上          2.41 12       7        4
AI-Three     压上          0.41 15       13       6
===================================
```

**`绕圈换向` 列非零（7 / 4 / 6）是 M4 生效的直接证据** ——
这个计数器只在 `BotDuelCircleDir()` 真正被调用时自增，
而它只在 `BotMoveEnemyDir()` 返回 `MOVE_CIRCLE` 且横移方向未被阻挡时才会被调到。
换句话说：三个机器人都确实执行过绕圈横移，并且换过方向。

### 2.4 三次报告中态势的演变

| 报告 | AI-One | AI-Two | AI-Three |
|---|---|---|---|
| 第 1 次 | 压上 16.66 | 压上 0.05 | 脱离 0.05 |
| 第 2 次 | 对枪 0.93 | 压上 1.65 | 压上 0.60 |
| 第 3 次 | 压上 5.40 | 压上 2.41 | 压上 0.41 |

优势比在 0.05 ~ 16.66 之间大幅波动 —— 这是**战斗真的在打**的特征，
而不是卡在某个常数上（那种情况通常意味着判定失效）。

日志：[`evidence/qconsole-repo-pipeline.log`](evidence/qconsole-repo-pipeline.log)

> **注意 `build_qagame.sh` 里的一个坑**：`q3asm.exe` 是原生 Windows 程序，
> 不认识 Git Bash 的 `/z/...` 风格路径。如果直接把 `$PWD`（MSYS 形式）喂给 `-o`，
> 它**不会报错**，而是把 qvm 写到别的地方去（看起来像"编译成功了但没有产物"）。
> 脚本里用 `pwd -W` 转了 Windows 路径。

## 5. 验证方法的说明

### 为什么用"计数"而不是"视频"

绕圈横移（M4）和"提前占位"（M2）这类行为很难从截图里判定 ——
静态帧看不出"在绕圈"还是"在直走"。所以每个模块都配了**运行时计数器**：

| 模块 | 证据 | 位置 |
|---|---|---|
| M1 | 玩家画像报告（热度 / 蹲守% / 常用武器 / 热点区域） | `bot_profile_debug 1` |
| M2 | `zzqAI M2: <bot> 提前 N.Ns 去占位 <物品>` | `bot_item_wait_diag 1` |
| M3 | `zzqAI M3: <bot> 态势 X -> Y (优势比 ...)` | `bot_duel_debug 1` |
| M3 | 压上 / 脱离 计数 | `bot_duel_report 1` |
| M4 | 绕圈换向 计数 | `bot_duel_report 1` |

计数非零 = 代码路径确实被执行过。这比"看着像在绕圈"可靠得多。

### 已知不足

1. **没有做 bot vs 原版的胜率对照实验**。本记录只能证明功能生效，不能定量证明
   "更强"。定量评测需要固定图 + 固定技能 + 多局统计胜率 / 物品控制率 / 存活时长，
   且样本要足够大。
2. M4 的"绕圈是否真的更难被打中"没有量化指标。合理做法是统计被击中率
   （brainworks 自带 `bot_accuracy_t` 统计，可以扩展读取）。
3. 只在 q3dm4 单图上验证过。其它地图（尤其是多层 / 有跳台 / 有岩浆的图）需要复测。

## 6. 复现命令

```bash
cd <Quake3 安装目录>

# 实验组（M1–M4 全开）
./quake3e.x64.exe +set fs_game brainworks +set logfile 1 \
                  +devmap q3dm4 +exec m3test.cfg

# 对照组（全关）
./quake3e.x64.exe +set fs_game brainworks +set logfile 1 \
                  +devmap q3dm4 +exec m34control.cfg

# 看结果
grep "zzqAI M3" brainworks/qconsole.log
grep -A6 "决斗态势报告" brainworks/qconsole.log
grep -ciE "^Error|Program error|Fatal" brainworks/qconsole.log
```

配置里的 `wait N` 是 **N 个服务器帧（20 Hz）**，
`wait 1500` ≈ 75 秒 —— 机器人进场很晚，给少了会看到"什么都没发生"。
