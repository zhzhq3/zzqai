### 2.3 汇总报告

```
$ bot_duel_report 1
===== zzqAI M3/M4 决斗态势报告 =====
机器人    态势   优势比 压上   脱离   绕圈换向
AI-One       压上          5.40 19       15       7
AI-Two       压上          2.41 12       7        4
AI-Three     压上          0.41 15       13       6
```

**`绕圈换向` 列非零（7 / 4 / 6）是 M4 生效的直接证据** ——
这个计数器只在 `BotDuelCircleDir()` 真正被调用时自增，
而它只在 `BotMoveEnemyDir()` 返回 `MOVE_CIRCLE` 且横移方向未被阻挡时才会被调到。
换句话说：三个机器人都确实执行过绕圈横移，并且换过方向。

### 2.4 三次报告中态势的演变

| 报告 | AI-One | AI-Two | AI-Three |
|---|---|---|---|
| 第 1 次 | 压上 16.66 | 压上 0.05 | 脱离 0.05 |
| 第 2 次 | 对枪 0.93 | 压上 1.65 | 压上 0.60 |
| 第 3 次 | 压上 5.40 | 压上 2.41 | 压上 0.41 |

优势比在 0.05 ~ 16.66 之间大幅波动 —— 这是**战斗真的在打**的特征，

## 6. 验证方法的说明

### 为什么用"计数"而不是"视频"

绕圈横移（M4）和"提前占位"（M2）这类行为很难从截图里判定 ——
静态帧看不出"在绕圈"还是"在直走"。所以每个模块都配了**运行时计数器**：

| 模块 | 证据 | 位置 |
|---|---|---|
| M1 | 玩家画像报告（热度 / 蹲守% / 常用武器 / 热点区域） | `bot_profile_debug 1` |
| M2 | `zzqAI M2: <bot> 提前 N.Ns 去占位 <物品>` | `bot_item_wait_diag 1` |
| M3 | `zzqAI M3: <bot> 态势 X -> Y (优势比 ...)` | `bot_duel_debug 1` |
| M3 | 压上 / 脱离 计数 | `bot_duel_report 1` |
| M4 | 绕圈换向 计数 | `bot_duel_report 1` |
| M5 | `zzqAI M5: <bot> 得分 X / 同场均分 Y -> 偏移 Z` | `bot_adaptive_debug 1` |
| M5 | 原始 / 偏移 / 有效 skill 表 | `bot_adaptive_report 1` |
| M6 | `zzqAI M6: <bot>（角色）收到 <队友> 的情报 -> 距 N` | `bot_share_debug 1` |
| M6 | 角色分工 + 每台机器人的接收计数 + 情报板条数 | `bot_share_report 1` |

计数非零 = 代码路径确实被执行过。这比"看着像在绕圈"可靠得多。

### 已知不足

1. **没有做 bot vs 原版的胜率对照实验**。本记录只能证明功能生效，不能定量证明
   "更强"。定量评测需要固定图 + 固定技能 + 多局统计胜率 / 物品控制率 / 存活时长，
   且样本要足够大。
2. M4 的"绕圈是否真的更难被打中"没有量化指标。合理做法是统计被击中率
   （brainworks 自带 `bot_accuracy_t` 统计，可以扩展读取）。
3. M1–M4 主要在 q3dm4 单图上验证，M6 在 q3dm6（TDM）上验证。
   其它地图（尤其是多层 / 有跳台 / 有岩浆的图）需要复测。
4. M5 的伺服基准是"全场平均分"。如果场上有个挂机不动的玩家，所有机器人都会被
   整体压低一点；真实对局中玩家会得分，这个偏移自然消失。

## 7. 复现命令

```bash
cd <Quake3 安装目录>

# M1–M4 实验组
./quake3e-vulkan.x64.exe +set fs_game brainworks +set logfile 1 \
                  +devmap q3dm4 +exec m3test.cfg

# M1–M4 对照组
./quake3e-vulkan.x64.exe +set fs_game brainworks +set logfile 1 \
                  +devmap q3dm4 +exec m34control.cfg

# M5 难度伺服（FFA，两组不同初始 skill）
./quake3e-vulkan.x64.exe +set fs_game brainworks +set logfile 1 \
                  +devmap q3dm4 +exec m5test.cfg

# M6 团队情报（TDM！必须显式设 g_gametype 3）
./quake3e-vulkan.x64.exe +set fs_game brainworks +set logfile 1 \
                  +set g_gametype 3 +devmap q3dm6 +exec m6test.cfg

# M5 + M6 对照组
./quake3e-vulkan.x64.exe +set fs_game brainworks +set logfile 1 \
                  +set g_gametype 3 +devmap q3dm6 +exec m56control.cfg

# 看结果
grep "zzqAI M3\|zzqAI M5\|zzqAI M6" brainworks/qconsole.log
grep -A8 "难度伺服报告" brainworks/qconsole.log
grep -A9 "团队情报报告" brainworks/qconsole.log
grep -ciE "^Error|Program error|Fatal" brainworks/qconsole.log
```

配置文件都在仓库的 `config/` 目录。

配置里的 `wait N` 里的 N 是**客户端帧**（quake3e 约 57 fps）。
`wait 1500` ≈ 26 秒 —— 机器人进场很晚，给少了会看到"什么都没发生"。
`m5test.cfg` / `m6test.cfg` 累计约 6600 帧 ≈ 115 秒，需要耐心等。
