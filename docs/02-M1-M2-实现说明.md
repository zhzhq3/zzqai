## 2. M1 对手档案

**数据结构**（每个玩家一份，`MAX_CLIENTS × sizeof(player_profile_t)` ≈ 10 KB）：

```c
typedef struct player_profile_s {
    float  heat[MAX_REGIONS];            // 各区域"停留秒数"，按 0.06/秒 衰减（时间常数≈16.7s）
    float  heat_total, camp_time, move_time;
    float  weapon_time[WP_NUM_WEAPONS];  // 观察到持各武器的时间
    int    last_region, deaths;
    float  alive_time, last_death_time;
    qboolean was_alive;
    float  seen_time;   vec3_t seen_origin;   // 最后一次被察觉的位置
} player_profile_t;
```

**更新时机**：每个服务器帧（`LevelProfileUpdate`），遍历所有在场玩家，累计区域热度、
按速度（<40 单位/秒 = 蹲守）分「蹲守/移动」，记录当前武器；存活→死亡瞬间 `deaths++`。

**怎么用**：机器人丢失敌人时，`BotSelectSearch` 原本在 16 个方向里**随机**挑一个看。
现在改为：`ProfilePrediction()` 综合"该敌人总热度 × 热点区域热度 × 与我的距离权重"，
选出最该看的区域，再挑方向最贴近该区域的候选点。**没有画像数据时行为与原来完全一致。**

**设计取舍**：热度只统计"区域内停留时长"，位置记忆只在敌人**被察觉时**更新，
不读取隐身敌人的实时坐标，所以不是透视挂。

## 3. M2 物品提前占位

**问题**：原版 `BotItemClusterSetConsider()` 里有一句

```c
if (pickup_time < this_option->soonest_respawn) { isi_skip(&options); continue; }
```

意思是"如果我到的时候物品还没刷出来，就干脆不去"——所以机器人**永远不会提前到位等刷新**，
而真人高手的物品控制恰恰是"提前 1~2 秒占住刷新点"。

**改法**：把阈值放宽 `bot_item_wait` 秒，并让资源预测按真实刷新时刻计入（否则提前占位拿不到东西会被打分淘汰）。

```c
if (pickup_time + bot_item_wait.value < this_option->soonest_respawn) { skip; }
...
if (this_option->soonest_respawn > item_respawn_time &&
    this_option->soonest_respawn <= pickup_time + bot_item_wait.value)
        item_respawn_time = this_option->soonest_respawn;
```

`bot_item_wait = 0` 时与原版**逐字节等价**（已验证，见下）。

## 4. cvar 一览

| cvar | 默认 | 说明 |
|---|---|---|
| `bot_profile` | 1 | 对手档案总开关（影响搜索方向） |
| `bot_profile_debug` | 0 | 置 1 打印一次全部玩家画像后自动清 0 |
| `bot_item_wait` | 2.0 | 提前到位等待的秒数，0 = 关闭，退回原版 |
| `bot_item_wait_diag` | 0 | 打印"提前占位"诊断（限速 2 秒一条） |

> 这些都是 `CVAR_CHEAT`（沿用 brainworks 对 AI 调参 cvar 的一贯做法）。
> 想现场改：用 `devmap <map>` 开图（自动开作弊），再 `exec zzqbot.cfg`。

## 6. 已知问题与下一步

- 测试里 `addbot default` 报 `Bot 'default' not defined`——因为 `brainworks.pk3` 里只有 `zzqbot_c.c`，
  没有内置角色文件。**与本改动无关**，用 `addbot zzqBOT` 即可。
- M2 目前只对"机器人自己记着刷新时间"的簇生效（需要它自己看过/听见过该物品被拿）。
  下一步可做**关卡级物品时钟**，让全队共享刷新时刻。
- M1 的预测目前只用"长期热区"；下一步可叠加"最后已知位置 + 移动方向外推"。
- 第三步计划的 M3 决斗策略机 / M4 移动技法宏 / M5 自适应难度 / M6 团队角色尚未开始。
