> 配套源码：`code/game/ai_duel.c`、`code/game/ai_duel.h`，以及 `ai_move.c` /

---

## 0. 为什么是"决策层"

把 brainworks 的能力摊开看，它缺的正好是**一层**：

```
感知层   ai_scan / ai_aware       ✅ 视觉 + 听觉（按声量给半径）
感知层   ai_motion                ✅ 位置插值 + 延迟补偿
记忆层   aware_record[]           ✅ 带衰减的"我见过谁、在哪"
评估层   BotEnemyDamageRatio      ✅ 伤害交换比
执行层   ai_attack / ai_move      ✅ 提前量 / 瞄准 / 走位 / 闪避 / strafe jump
──────── 这里是空的 ────────
决策层   "这一场要不要打？"        ❌  全工程 `duel` 关键字 0 命中
决策层   "打不过怎么办？"          ❌
决策层   "什么时候该去占物品？"     ❌（M2 补）
决策层   "这对手习惯在哪？"        ❌（M1 补）
```

已有的 `game_style` / 目标筛（goal sieve）只区分 CTF / 队伍 / 单人模式，
单人模式下就是"看到敌人 → 打"，没有"值不值得"的判断。

M3 补的是前两条，M4 补的是这层判断**落到脚上**的部分。

## 1. M3 决斗策略机

### 1.1 优势比：口径比数值重要

最容易犯的错是拿血量比血量。Q3 里 100 血 + 100 甲和 200 血 + 0 甲完全不是一回事。
brainworks 已经有一个正确的口径：

```c
// ai_entity.c
int EntityHealth(gentity_t *ent)
{
    health = HealthArmorToDamage(ps.stats[STAT_HEALTH], ps.stats[STAT_ARMOR]);
    if (ent->s.powerups & (1 << PW_BATTLESUIT))
        health *= 2;                  // 战衣半伤 ≈ 双倍血
    ...
}
```

所以：

```c
my_stack    = EntityHealth(bs->ent);     // 我方"可承受伤害"
enemy_stack = BotEnemyHealth(bs);        // 敌方估计（brainworks 原本就有）
advantage   = my_stack / enemy_stack;
```

`BotEnemyHealth()` 是 brainworks 已有的敌方血量估计：

- skill ≥ 4 或非玩家目标 → 直接读真实血量（相当于高水平玩家"手感准"）
- 其他 → 靠痛叫声累计的 `bs->enemy_health`

**敌方护甲不可观察，按 0 计。** 这是刻意的保守方向：宁可低估自己的优势，
也不会让机器人因为高估而鲁莽。不引入任何"作弊式"的完整信息。

### 1.2 态势判定（顺序即优先级）

```c
if (我方有 Quad && 敌方没有)              PRESS      // 这个窗口不用来杀人就是浪费
else if (enemy_stack <= 45)               PRESS      // 对面残血，别让他跑回去补
else if (my_stack <= 55 || adv < 0.80)    DISENGAGE  // 血甲见底 或 换血吃亏
else if (adv >= 1.45 && my_stack >= 85)   PRESS
else                                      TRADE
```

阈值都在 `ai_duel.c` 顶部定义，方便调参。

### 1.3 迟滞：不让机器人在阈值上抖动

```c
if (bs->duel_stance != DUEL_STANCE_NONE &&
    bs->duel_stance != stance &&
    stance != DUEL_STANCE_DISENGAGE &&                          // ← 进入脱离不设延迟
    (bs->command_time - bs->duel_stance_time) < 0.35)
{
    stance = bs->duel_stance;                                   // 维持旧态势
}
```

**保命立即，恢复延迟** —— 这是不对称的，和人的反应一致。

### 1.4 "正在交战"的判定

只用 `bs->aim_enemy` 会漏掉"背后挨枪"的情况，所以补一个挨打计时：

```c
if (bs->duel_last_stack > my_stack + 0.5)
    bs->duel_damage_time = bs->command_time;        // 本帧可承受伤害掉了

qboolean BotDuelEngaged(bs) {
    return bs->aim_enemy || (bs->command_time - bs->duel_damage_time) < 3.0;
}
```

注意这用的是**数值变化**而不是读别人的实时坐标，不构成任何透视。

### 1.5 脱离时去哪：`BotGoalDuelChoice`

```c
int BotGoalDuelChoice(bot_state_t *bs, bot_goal_t *goal)
{
    if (!bot_duel.integer)                                    return GOAL_NONE;
    if (!BotDuelEngaged(bs) ||
        BotDuelStance(bs) != DUEL_STANCE_DISENGAGE)           return GOAL_NONE;

    item = BotDuelRegroupItem(bs);      // 最近的血包/护甲
    if (!item)                                                return GOAL_NONE;
    if (!GoalEntity(goal, item))                              return GOAL_NONE;
    if (!BotPathPlan(bs, &bs->main_path, goal, goal))         return GOAL_NONE;

    BotSetTeamStatus(bs, TEAMTASK_RETRIEVE);
    return GOAL_DUEL_REGROUP;
}
```

关键在 `BotDuelRegroupItem()` 的过滤条件 —— **不朝枪口跑**：

```c
// 物品到敌人的距离必须大于物品到自己的距离
if (enemy_dist < dist)
    continue;
```

没有这一条，"脱离"就会变成"朝着敌人撤退"。这是整个模块最容易写错的地方。

目标筛里的位置（`BotComputeGoalCheckList`）：

```c
BotAddGoalCheck(bs, BotGoalDuelChoice);      // ← 必须先于"追敌"
BotAddGoalCheck(bs, BotGoalAttackChoice);
```

`BotGoalAttackChoice` 排在前面的话，原版的追敌目标会先命中，一切白做。

### 1.6 动作链里的位置

```c
{ BotActionMoveSetup,  AFC_INGAME|AFC_ALIVE|AFC_PLAY|AFC_RFXLGC },
{ BotActionDuel,       AFC_INGAME|AFC_ALIVE|AFC_PLAY|AFC_RFXLGC },   // ← 新增
{ BotActionGoal,       AFC_INGAME|AFC_ALIVE|AFC_PLAY|AFC_LOGIC  },
{ BotActionMoveSelect, AFC_INGAME|AFC_ALIVE|AFC_PLAY|AFC_RFXLGC },
```

- 必须在 `BotActionGoal` **之前** —— 目标选择要读态势。
- 必须在 `BotActionMoveSelect` **之前** —— 走位要读态势。
- 用 `AFC_RFXLGC`（每个反射帧）而不是 `AFC_LOGIC`：血量随时会掉，
  "该不该脱战"不能等逻辑帧。

## 2. M4 战斗走位

### 2.1 绕圈横移（circle strafe）

原版 `BotMoveEnemyDir()` 在算出理想交火距离后是这样收尾的：

```c
// Stand still if in or near the ideal distance
if (fabs(best_dist - dist) < 32.0)
    return MOVE_STILL;              // ← 原地站桩
```

原地站着是这个 AI 最容易被打中的状态。改成：

```c
if (fabs(best_dist - dist) < 32.0)
    return BotDuelShouldCircle(bs) ? MOVE_CIRCLE : MOVE_STILL;
```

然后在 `BotMoveEnemy()` 里处理 `MOVE_CIRCLE`：

```c
if (dir == MOVE_CIRCLE)
{
    BotDuelCircleDir(bs, ent, circle);        // 垂直于"敌人→我"的水平向量
    if (BotTestMove(bs, circle))
    {
        BotMoveDirection(bs, moveresult, circle, 400, MOVE_WALK);
        bs->dodge_chance = bot_dodge_rate.value;
        return qtrue;
    }
    dir = MOVE_STILL;                         // 横移被挡住就退回原地
}
```

**为什么这不破坏瞄准**：`BotMoveDirection()` 只发移动指令，
视角完全由 `ai_view.c` / `ai_aim.c` 那条链负责，两者正交。
所以机器人可以一边横移一边稳稳地把准星压在敌人身上 —— 这正是真人 circle strafe 的效果。

方向每 1.4 秒随机换一次（`duel_circle_side`），避免变成可预测的匀速绕圈：

```c
if ((bs->command_time - bs->duel_circle_time) > DUEL_CIRCLE_SWITCH)
{
    bs->duel_circle_time = bs->command_time;
    bs->duel_circle_side = (rand() & 1) ? 1 : -1;
    bs->duel_circle_count++;                  // ← 诊断计数，验证时看这个
}
```

### 2.2 劣势后撤（边退边打）

在 `BotMoveEnemy()` 开头拦截：

```c
if (BotDuelShouldRetreat(bs))
{
    BotDuelRetreatDir(bs, ent, backward);
    if (BotTestMove(bs, backward))
    {
        BotMoveDirection(bs, moveresult, backward, 400, MOVE_WALK);
        bs->dodge_chance = bot_dodge_rate.value;
        return qtrue;
    }
}
```

`BotDuelRetreatDir()` = 背离敌人 + 最多 35° 横向偏角（避免退成一条直线被预判）。
因为瞄准链没被动过，机器人会**面朝敌人一边后退一边开枪**。

### 2.3 为什么不复用 `MM_DODGE`

brainworks 的闪避（`ai_dodge.c`）是"半随机向前移动"，是为了躲**已发射的弹体**，
不是战术走位：它不考虑交火距离是否理想，也不会持续绕圈。两者解决不同问题，
所以新增 `MOVE_CIRCLE` 而不是改 `MM_DODGE`。

## 3. 关闭时的行为

`BotDuelUpdate()` 开头就短路：

```c
if (!bot_duel.integer && !bot_duel_move.integer)
{
    bs->duel_stance = DUEL_STANCE_NONE;
    bs->duel_advantage = 1.0;
    bs->duel_last_stack = 0.0;
    return;                      // 不判定、不计数、不打印
}
```

加上 `BotGoalDuelChoice()` 与 `BotDuelShouldRetreat/Circle()` 各自开头的 cvar 检查，
两个 cvar 都设 0 时：**零日志、零目标变化、零走位变化**，完全等同原版。
对照组实验已经验证（见 `05-验证记录.md`）。

## 4. 调参入口

| 常量 | 位置 | 默认 | 含义 |
|---|---|---|---|
| `DUEL_RETREAT_STACK` | ai_duel.c | 55.0 | 自身可承受伤害低于此值 → 考虑脱离 |
| `DUEL_RETREAT_ADV` | ai_duel.c | 0.80 | 优势比低于此值 → 考虑脱离 |
| `DUEL_PRESS_ADV` | ai_duel.c | 1.45 | 优势比高于此值 → 压上 |
| `DUEL_PRESS_STACK` | ai_duel.c | 85.0 | 压上要求的自身可承受伤害 |
| `DUEL_PRESS_ENEMY_LOW` | ai_duel.c | 45.0 | 敌方残血阈值 |
| `DUEL_STANCE_COMMIT` | ai_duel.c | 0.35 | 态势最短维持（秒） |
| `DUEL_ENGAGE_TIMEOUT` | ai_duel.c | 3.0 | 挨打后仍算交战的时间（秒） |
| `DUEL_CIRCLE_MIN/MAX_DIST` | ai_duel.c | 72 / 768 | 绕圈的距离窗口 |
| `DUEL_CIRCLE_SWITCH` | ai_duel.c | 1.4 | 绕圈换向间隔（秒） |
| `DUEL_REGROUP_MAX_DIST` | ai_duel.c | 1600 | 脱离时愿意去找补血甲的最远距离 |
