# Quake 3 机器人 AI 三方对比 与「第四代」模组可行性设计

> 日期：2026-10-09　｜　环境：`D:\Quake 3 Arena-vulkan`（engine = `quake3e-vulkan.x64.exe`，加载 QVM）
> 对象：`Z:\q3brainworks`（brainworks）、`Z:\Quake3AI-master`、`Z:\Quake3bot-master`

---

## 0. 一句话结论

**这三个东西不在同一个层次上，所谓"三家对比"其实是"一家 + 一个半成品 + 一份角色数据"。**

- **能不能做得比这三个都强？——能。** 但"更强"必须落在**决策质量**上（物品控制、团队、对手建模、拟人感知），
  而不是堆反应速度和命中率——brainworks 的枪法参数本来就能调到超人类。
- **最省力的路径**：**以 brainworks 为基座**（我们已经有可用的 q3lcc/q3asm 工具链 + pk3 打包管线），
  增量补上它真正缺的 6 个维度。Quake3AI 的 navmesh 思路可以参考，但它的引擎层改造进不了 `quake3e`。

## 1. 三者到底是什么

| 项目 | 本质 | 代码量 | 运行形态 | 能否直接用在 quake3e |
|---|---|---|---|---|
| **brainworks**（`Z:\q3brainworks`） | **完整 AI 引擎**，AI 全部搬进 game 模块 | **33,186 行** / 36 个 `ai_*.c`（其中 4 个是 3 行占位） | **纯 QVM**，`qagame.qvm` 丢进 pk3 即生效 | ✅ **已在跑** |

### 关键澄清

- **Quake3bot-master 不是 AI 模组。** 它只有 `War_c.c`（角色）、`War_w.c`/`War/fw_weap.c`（武器权重）、
  `War_i.c`/`War/fw_items.c`（物品权重）、`War_t.c`（聊天）+ 皮肤/模型/音效。
  真正"决定聪明程度"的是**上层 AI 引擎**，这份文件只贡献"性格与偏好"。→ 我们做 zzqBOT 时用的就是它的 War 角色。
- **Quake3AI-master 是个半成品。** 关键文件被大面积注释掉：

  | 文件 | 总行 | 注释/禁用 | 比例 |
  |---|---|---|---|
  | `BotAI/BotAI_ltg.c` | 1,173 | 980 | **83%** |
  | `BotAI/BotAI_deathmatch.c` | 414 | 276 | **66%** |
  | `BotAI/BotAI_battle.c` | 966 | 400 | 41% |
  | `BotAI/BotAI.c` | 970 | 296 | 30% |
  | 对照 brainworks | | | 19%–29%（正常文档注释） |

  即：**"长期目标 AI"（LTG）几乎整段被关掉**，`BotAllocMoveState()` 等调用也是注释状态。它是一份**写到一半停下的重写工程**。
- 它的亮点只有一个：**用 recast/detour navmesh 替换 AAS 寻路**（`trap_Nav_GetPathBetweenPoints` /
  `trap_Nav_GetRandomPointNearPosition` / `trap_Nav_LoadMesh`），并配套写了 `bspnav` 工具把 `.bsp` 烘焙成 `.nav`。
  代价是**必须改引擎**——`quake3e` 没有这些系统调用。

## 3. brainworks 具体强在哪（证据）

- `ai_scan.c`：**听觉模型**——`EV_FOOTSTEP_METAL` 512、`EV_JUMP_PAD`/`EV_FIRE_WEAPON` 1024、
  `EV_BULLET_HIT_WALL` 256，按声音大小给不同感知半径。多数 Q3 bot 只会"看"。
- `ai_main.h` 的 `bot_state_t`：`enemy_health`（**靠 pain 声估血**）、`teleport_enemy_*`（追踪传送到哪）、
  `aware_record[]`/`aware_timeout[]`（**带衰减的实体记忆表**）、`kills_per_damage`（伤害→收益换算）。
- `ai_attack.c`：`bot_attack_lead_time_full` / `lead_time_scale`（**射击提前量**）、
  `careless/careful_factor`（按目标包围盒缩放做命中误差，拟人化而不是精确锁头）。
- `ai_view.c`：视角有**加速度/角速度上限**（`view_actual_accel_min/max`），不是瞬间转头。
- `ai_item.c`：把物品按**簇（cluster）**组织，计算簇的最长重生延迟并**预测计时**（`ItemRespawn`）。
- `ai_maingoal.c`（1763 行）：主目标效用评估；`ai_resource.c`（2311 行）：血量/护甲/弹药资源系统。
- 全 AI 只用 AAS 做路径（`trap_AAS_PredictRoute` 等 11 处），**不依赖 botlib 的决策**——所以它能被完整替换。

## 4. 三者共同的短板 —— 这正是"第四代"的机会

| # | 缺口 | 说明 | 难度 |
|---|---|---|---|
| 1 | **长期对手建模** | 没有跨回合记忆：玩家爱走哪条路、爱在哪蹲、爱用什么枪、命中率多少。现在每帧都在"重新认识你" | 中 |
| 2 | **主动物品控制** | 现在是"看到就捡 + 簇计时"；高手是**主动算准 mega/RA/quad 刷新点，提前 1–2 秒占位、卡对手** | 中 |
| 3 | **1v1 决斗策略** | Q3 的含金量在 duel（控制物品循环、算血量、进退时机）。现有 AI 都是 DM/团队导向，**`duel` 关键字在全工程 0 命中** | 高 |
| 4 | **高级移动** | strafe-jump / circle jump / rocket jump 提速转点——**速度就是物品控制的前提**。brainworks 有 strafe/rocketjump 但很基础 | 高 |
| 5 | **连续自适应难度** | 现在只有 `skill 1–5` 五档；理想是**连续曲线**跟着玩家表现走，永远"刚好比你强一点" | 低 |
| 6 | **团队分工与情报共享** | 现在有 flag/carrier/escort，但没有**角色化（突破/防守/护送）+ 共享敌人情报**（"敌人在 RA"） | 中 |

## 5. 「第四代」设计草案（代号 **zzqAI / Omega**）

### 5.1 分层架构（在 brainworks 内核外裹三层）

```
┌─ 元层 Meta ───────────── 自适应难度曲线、调试面板、参数热调
├─ 决策层 Decision ─────── 目标效用函数 │ 决斗策略机 │ 团队角色分配
├─ 世界模型 World Model ── 物品计时表 │ 对手档案 │ 地图控制热力
└─ 感知层 Perception ───── 视觉 + 听觉 + 带衰减记忆   ← 沿用 brainworks
   执行层 Execution ─────── 移动(AAS+技法宏) │ 瞄准 │ 开火     ← 沿用 brainworks
```

**原则：不动 brainworks 已经好的部分（感知/瞄准/听觉），只在"世界模型 + 决策"这两层加东西。**

### 5.2 六个可落地模块

| 模块 | 内容 | 落点（文件） |
|---|---|---|
| **M1 对手档案** | 每局累计：区域访问频次、蹲守时长、常用武器、命中率、死亡位置 → 生成"行为热力图"，用于预测与卡位 | 新增 `ai_profile.c` |
| **M2 物品时钟** | 记录 mega/RA/quad/flag 的**精确刷新时刻**，规划"到点前 1–2s 已在位"的路线；支持**反占位**（对手快到时提前卡身位） | 扩 `ai_item.c` |
| **M3 决斗策略机** | 用 `enemy_health` 估值 + 双方护甲/武器差 → 决策"打/退/换位控物品"；控物循环（RA→mega→YA→RA） | 新增 `ai_duel.c` |
| **M4 移动技法宏** | 直线段用 circle-jump/strafe-jump 提速；固定跳点用 rocket-jump；做成"路线宏"而非逐帧解算 | 扩 `ai_move.c` |
| **M5 自适应难度** | 连续 skill ∈ [0,1]，按近期玩家 KD / 命中 / 存活时长回归，**目标胜率可设定** | 扩 `ai_vars.c` + 新增 cvar |
| **M6 团队角色** | 按队伍状态动态分配：突破手/守点/护旗/换旗；**共享敌人位置**（复用 aware 表做队伍级广播） | 扩 `ai_team.c` |

### 5.3 可选：navmesh 寻路
- **不建议一期做**。quake3e 不提供 `trap_Nav_*`，要改引擎二进制，风险大、收益有限（AAS 在标准图上够用）。
- 如果要做，正确姿势是**参考 Quake3AI 的 `bspnav`**，把 recast/detour 编译进引擎，逐图烘焙 `.nav`；
  但那是"换腿"，不是"换脑"——对"更聪明"帮助很小。

## 6. 可行性、工作量与风险

**能做的核心理由**
1. 基座可编译、可运行（工具链已打通，`qagame.qvm` 字节级可比对官方）。
2. brainworks 的 AI 与执行层解耦良好（只依赖 AAS 路径 + 事件扫描），方便插桩。
3. 六个模块**互相独立**，可以一个一个加、一次一次测、随时回滚。

**评测方法（关键，否则"更强"没有定义）**
- 固定地图 + 固定技能，跑 **bot vs bot 定局对战**（比如 20 局），统计：
  胜率 / 每分钟击杀 / **物品控制率**（谁先到 mega/RA）/ 平均存活时长 / 平均伤害效率。
- 对照基线：brainworks 原版同技能。**每一项都要有数字，不靠感觉。**

**风险与红线**
- QVM 内存/性能有限（33k 行已经不小），新增模块要注意分配器与每帧开销。
- AAS 依赖地图 `.aas` 文件，自定义图要先有 `.aas`。
- ⚠️ **不要把"更强的 AI"做成"超人类枪法"**——把命中调到 100% 只会让人恶心，不叫智能。
  真正像人的强，是**物品控制、走位、时机、团队**。

## 7. 建议的三步走

| 阶段 | 目标 | 验收 |
|---|---|---|
| **第一步** | 对手档案 M1 + 物品时钟 M2 | 定局对战里"先拿到 mega"的比例显著上升 |
| **第二步** | 决斗策略机 M3 + 移动技法 M4 | 1v1 对 brainworks 原版胜率 > 55% |
| **第三步** | 自适应难度 M5 + 团队 M6 | 玩家体感"越打越难、但打得过"；团队局有配合行为 |
