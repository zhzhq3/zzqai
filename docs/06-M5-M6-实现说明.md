## 一、M5 连续自适应难度

### 1.1 原版的问题

brainworks 的 `skill` 是一个 1~5 的整数，在 `addbot` 时定死，之后全程不变：

- 玩家越打越强，机器人还是开局那个水平；
- 一支队伍里所有机器人共用一个 skill，强的更强、弱的更弱，对局很快失衡；
- 想调难度只能整局重开。

### 1.2 做法

给每个机器人单独算一个 **skill 偏移**（-1.5 ~ +1.5），并把它叠加到原始 skill 上：

```
有效 skill = clamp(原始 skill + 偏移, bot_adaptive_min, bot_adaptive_max)
```

偏移的来源是"**这个机器人的得分**"和"**同场其他玩家的平均得分**"的差距：

```
peer     = (全场总分 - 自己得分) / (在场人数 - 1)     // 参照系
err      = (peer - 自己得分) / (|peer| + |自己得分| + 1)   // 归一化到 [-1, 1]
目标偏移 = err × bot_adaptive_range
偏移    += clamp(目标偏移 - 偏移, -rate, +rate)      // 每周期最多移动 rate
```

- 得分落后（`err > 0`）→ 偏移变正 → 机器人变强；
- 得分领先（`err < 0`）→ 偏移变负 → 机器人放水。

评估每 `bot_adaptive_interval`（默认 6）秒做一次。

### 1.3 零侵入的实现方式

**没有任何一处读取 `bs->settings.skill` 的代码被改动。** 本模块每个服务器帧把
`原始 skill + 偏移` 写回 `bs->settings.skill`，于是所有依赖 skill 的逻辑自动跟随：

| 读取 skill 的位置 | 受影响的行为 |
|---|---|
| `ai_aware.c` | 感知半径与记忆时长 |
| `ai_scan.c` | 起跳/落地的听觉判定阈值 |
| `ai_self.c` | 瞄准精度与反应档位 |
| `ai_pickup.c` | 物品预测深度 |
| `ai_move.c` | 加速跳跃的启用门槛 |

写回时会先做一个**自愈检测**：如果发现 `bs->settings.skill` 和上一帧写入的值对不上
（例如这个 client 位置换了另一个机器人，或者有外部代码改写过），就以当前值为新的
原始 skill、偏移清零。

> 说明：botlib 的角色数据（`trap_BotLoadCharacter`）在加载时已按原始 skill 冻结，
> 运行期改 skill 不会重载性格文件；但上面这些"每帧读 skill"的逻辑全部会跟着变。

### 1.4 实测（`config/m5test.cfg`，q3dm4，4 个 zzqBOT）

故意放两组不同初始 skill 的机器人：`Low*` 是 skill 2，`High*` 是 skill 4。
Low 打不过 High，得分低，应该被抬起来；High 得分高，应该被压下去。

**开局与结束时的对比：**

| 机器人 | 原始 skill | 偏移 | 有效 skill | 得分 | 同场均分 |
|---|---|---|---|---|---|
| zzqBOT-Low1 | 2.00 | −0.17 | 1.82 | 9 | 7.0 |
| zzqBOT-Low2 | 2.00 | **+0.65** | **2.65** | 3 | 8.5 |
| zzqBOT-High1 | 4.00 | **−0.59** | **3.40** | 14 | 5.7 |
| zzqBOT-High2 | 4.00 | −0.36 | 3.63 | 11 | 6.5 |

- 得分最低的 `Low2`（3 分）被抬到 **2.65**；得分最高的 `High1`（14 分）被压到 **3.40**。
- 两组的 skill 差距从 **2.00** 收敛到 **0.75**。
- `Low1` 得 9 分，比 `Low2` 高，也就没有跟着一起涨（−0.17）—— 说明是**按个体表现**
  伺服，不是按初始档位。`High1`（14 分）比 `High2`（11 分）压得更狠，同理。

评估了 36 轮，140 条调整日志，全程 0 报错。

### 1.5 cvar

| cvar | 默认 | 作用 |
|---|---|---|
| `bot_adaptive` | 1 | 是否启用难度伺服 |
| `bot_adaptive_rate` | 0.30 | 每个评估周期最多移动的 skill 量 |
| `bot_adaptive_range` | 1.5 | 偏移的绝对值上限 |
| `bot_adaptive_min` | 1.0 | 有效 skill 下限 |
| `bot_adaptive_max` | 5.0 | 有效 skill 上限 |
| `bot_adaptive_interval` | 6.0 | 评估周期（秒） |
| `bot_adaptive_debug` | 0 | 实时打印调整 |
| `bot_adaptive_report` | 0 | 置 1 打印一次汇总并自动清零 |

## 二、M6 团队情报共享 + 角色化响应

### 2.1 原版的问题

brainworks 的团队机制很完整（队长选举、进攻/防守偏好、CTF 的夺旗回旗分配、语音指令），
但**缺了最基本的一条：互相告诉敌人在哪**。每个机器人看到的敌人只有它自己知道；
队友在那片区域被打死，其他人也不会知道。团队模式下常常是一堆各自为战的个体。

### 2.2 情报黑板

每个队伍一块黑板，`MAX_TEAM_INTEL`（8）个槽位，每条记录：

```
谁上报的（client 号）｜ 敌人在哪（坐标）｜ 什么时候上报的
```

- **写入端**：`ai_aware.c` 的 `BotAwareTrackEntity` —— 机器人**真的**通过视觉或听觉
  察觉到一个敌人时，把位置报进黑板（同时也调用 M1 的 `ProfileEnemySeen`）。
  一个人只占一个槽位，避免刷屏把队友的条目挤掉。
- **读取端**：目标选择里的 `BotGoalShareChoice`。

**关键的设计约束：自己报的情报不算数**（`board[i].reporter == bs->client` 直接跳过）。
自己的位置记忆是 M1（对手档案）负责的东西；共享黑板只提供"从队友那里听来的、
我自己没看到的"信息。这条约束保证情报共享**不会退化成给每个 bot 加透视**。

情报有存活时间（`bot_share_lifetime`，默认 8 秒），过期的自动作废。

### 2.3 目标顺序

`BotGoalShareChoice` 排在这三个检查之后：

```
BotGoalDuelChoice      ← M3：劣势补血甲
BotGoalAttackChoice    ← 原版：打自己看得见的敌人
BotGoalShareChoice     ← M6：去队友上报的情报点      ★
BotGoalItemChoice      ← 原版：去重要物品点碰运气
BotGoalCampChoice      ← 原版：兜底蹲点
```

放在 `BotGoalItemChoice` **之前**是有意的：队友刚上报的敌人位置是确凿信息，
比原版"去重要物品点碰运气"更值得跑一趟。

> 实测教训：这条目标一开始排在 `BotGoalItemChoice` **之后**，结果整局
> "收到情报"计数为 0 —— 原版目标总是先命中，M6 根本没机会执行。提前之后
> 立即出现 40 条接收日志。

### 2.4 角色化响应

队内成员按**进攻性**排序（`CHARACTERISTIC_AGGRESSION − 0.5 × CHARACTERISTIC_CAMPER`），
自动分工，不需要人工指定：

| 角色 | 谁担任 | 情报响应半径 |
|---|---|---|
| **突破 BREAKER** | 队内进攻性最高的 | × 1.00（全场都去） |
| **策应 ESCORT** | 中间成员 | × 0.75 |
| **守点 ANCHOR** | 队内进攻性最低的 | × 0.50（只响应附近的，不乱跑） |

角色在队伍成员变化时立即重算，另外每 5 秒兜底重算一次。

### 2.5 实测（`config/m6test.cfg`，q3dm6，TDM，红蓝各 2 个 zzqBOT）

```
机器人        队伍 角色 收到情报
zzqBOT-Red1      红    突破 65
zzqBOT-Red2      红    守点 35
zzqBOT-Blue1     蓝    突破 84
zzqBOT-Blue2     蓝    守点 106
红队情报板：2 条有效（有效期 10.0s，响应半径 4000）
蓝队情报板：2 条有效（有效期 10.0s，响应半径 4000）
累计情报上报 6323 条，开关 1
```

日志样例（`bot_share_debug 1`）：

```
zzqAI M6: zzqBOT-Red1（突破）收到 zzqBOT-Red2 的情报 -> 距 1894，情报龄 0.0s
zzqAI M6: zzqBOT-Blue1（突破）收到 zzqBOT-Blue2 的情报 -> 距 1129，情报龄 0.0s
```

- 角色分配正确：每队进攻性最高的当"突破"、最低的当"守点"。
- 40 条接收日志，四台机器人的接收计数全部非零。
- 0 报错。

### 2.6 cvar

| cvar | 默认 | 作用 |
|---|---|---|
| `bot_share` | 1 | 是否启用团队情报共享（仅团队模式生效） |
| `bot_share_lifetime` | 8.0 | 一条情报的有效期（秒） |
| `bot_share_range` | 2500 | 情报响应距离上限 |
| `bot_share_debug` | 0 | 实时打印收到的情报 |
| `bot_share_report` | 0 | 置 1 打印一次团队角色与情报板汇总并自动清零 |

## 五、已知局限（诚实说明）

1. **没有做 bot vs 原版的胜率对照。** 本页所有数据都是"功能确实在跑、关掉后确实
   退回原版"，**不能**用来定量声称"比原版更强"。要定量需要固定地图多局统计胜率、
   物品控制率、存活时长。
2. **M6 只在团队模式生效。** FFA 下没有队友，模块完全静默（`game_style & GS_TEAM`
   不成立时所有入口直接返回）。这是设计使然，不是缺陷。
3. **M5 的伺服基准是"全场平均分"**，所以在一个挂机玩家 + 一群机器人的极端场景下，
   所有机器人都会被整体压低一点。真实对局中玩家会得分，这个偏移自然消失。
4. **角色只有三种**（突破/策应/守点），且只影响情报响应半径。没有做"突破手去
   压制敌方半场""守点回基地"这类更细的分工 —— 原版已有 `BotGoalDefendChoice`
   等目标在管这些，不重复造轮子。
